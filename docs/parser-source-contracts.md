# Parser source contracts

> Factual contract matrix for the parser/source slugs represented by the Source schema parser enum and source seeder. This is a repository-evidence document, not a live availability report.

## Evidence boundary

- Evidence inspected: `api/src/api/source/content-types/source/schema.json`, `api/src/seeders/sources.ts`, `services/services.json`, the source adapters under `services/parser-*/src/sources/`, shared location/parser contracts, and parser tests.
- No HTTP request, browser probe, external API call, server, or production reparse was run while preparing this document.
- A value is marked `unknown`/`TODO` when the inspected code and docs do not prove it. A source URL is included only when it is a literal or a deterministic route in the adapter code; it is **not** a live-verification claim.
- `confirmed_address`, `confirmed_region_only`, and `missing` are the shared property-location statuses. `missing` is a valid fail-closed result, not permission to guess from unrelated text.

## Shared status and evidence rules

- Detail capability is explicit at runtime: adapters without `fetchDetails` are listing-only (`detail_supported=false`) for canary health. A no-op detail method is forbidden because it would fabricate successful hydration; real detail adapters must throw on transport/navigation/extraction failure instead of returning `{}`.
- `detail_supported` is persisted in every terminal source-stage snapshot and also governs normal-run health; it is never inferred from `details_attempted=0`.
- Every detail-capable adapter returns bounded `parser_diagnostics` built only from allowlisted semantic IDs. A missing verified property block is a truthful `property_block_missing` mismatch, not a fabricated healthy diagnostic; Roseltorg intentionally remains in that fail-closed state until a source-faithful field and fixture exist.
- Adapter failures carry an explicit allowlisted error class where known. Parser queue terminal errors, pipeline state and source/run telemetry persist only controlled `parser.<class>` / `pipeline.<class>` codes; raw exception messages, URLs, payloads and credentials are never copied from `job.error`. Cancellation reconciliation uses the queue's `cancellation_requested_at` state, never message-text inference.
- `schema_changed` and `blocked` are hard quarantine states for normal scan, details and direct manual parse. `null`, absent, unknown and malformed health values also fail closed; newly seeded sources start explicitly as `healthy`. The bounded read-only canary is the only intentional bypass. Worker health is re-read after scan counter reset immediately before `parser.parse()`, before detail adapter launch/fetch, and before Property persistence. Every normal/canary health writer fresh-reads and CAS-holds any current hard/unknown state; only the CAS winner may annotate the current run row or emit an alert.
- `confirmed_address`: an explicit property field produced a normalized address. It may also carry a region and coordinates when those came from the same typed property record.
- `confirmed_region_only`: an explicit property-region field exists, but no trusted full address exists. It must not be projected into the legacy address field.
- `missing`: no trusted property field exists. Do not infer from title, body, description, first address, party address, notification text, map text, or arbitrary JSON/XML values.
- `source_path` must identify the allowlisted source field/selector. A generic container or body path is not evidence of a property contract.
- Anti-bot/TLS entries above are deliberately narrow. A Playwright context, a timeout, a retry, or a delay alone does not prove a WAF, CAPTCHA, anti-bot block, or TLS failure.
